# Unit art recipe

How a unit's atlas is produced for every race, from one shared rig. The
Spearman (`art/units/spearman/`) is the worked example; the other eighteen
units follow the same steps. Everything here is generated by
`npm run build:atlases` from the sources under `art/`; nothing is painted by
hand and no image tool is needed beyond Node.

Races are referred to by their roster ids (`race1` … `race7`). Their display
names live only in `src/names/displayNames.ts` and must never appear in
`art/`, `public/` or `src/` (the build's name check enforces it for the
latter two).

## 1. The look

The original's flat vector style: solid fills, two tones per material (a
base colour and a darker back-limb tone), no outlines, an elliptical ground
shadow at 32 % black under the feet. Every figure faces +x (right); the
renderer mirrors it for the other side.

Authoring is at **4×**: the baseline figure stands about 112 px tall in the
atlas and 28 px in battle (lanes are 39 px apart on the 700 × 500 stage).
Keep a unit between 100 and 125 px tall at 4× (25–31 px at 1×); a unit that
must read shorter or taller does it through `proportions.height`.

## 2. Layer structure

A frame is drawn in painter's order, back to front, onto two canvases:

| Layer | Canvas | Content |
| --- | --- | --- |
| shadow | body | ground ellipse at the baseline |
| extras behind | body | tail, cloak |
| back arm + shield | body | darker tone |
| back leg | body | darker tone |
| torso | body | primary capsule, secondary tabard, leather belt |
| front leg | body | base tone, boot |
| head | body | skin, beard, helmet, horns, plume, crest |
| front arm + weapon | body | base tone; the weapon drawn after the hand |
| **accent** | accent | the team pennant, pure white, untinted |

The **body** canvas has the race palette baked in. The **accent** canvas is
white on transparent: the renderer uses it as a mask and fills it with the
side's value (white for the left side, black for the right), so two armies
of the same race stay apart. Never put colour on the accent layer and never
put the pennant on the body layer. Both canvases share one pivot — the
point between the feet on the baseline — which is what the atlas records.

## 3. The rig

`art/units/spearman/rig.mjs` is a 2D bone chain solved from a pose:

- hip → knee → ankle → toe, twice (front leg, back leg)
- hip → shoulder → neck → head
- shoulder → elbow → wrist → hand, twice (front: weapon; back: shield)
- weapon: a line through the front hand at `pose.spear`, held at `pose.grip`

`BASELINE` holds the neutral proportions, stance and parts. A race variant
is `defineVariant({...})` — a deep merge of overrides onto the baseline
(`art/units/races/<race>.mjs`). These are the knobs it offers:

| Group | Keys | Notes |
| --- | --- | --- |
| `proportions` | `height`, `legs`, `torsoWidth`, `shoulderWidth`, `headSize`, `limbWidth`, `handSize`, `stanceWidth`, `spearLength` | multipliers, 1 = baseline |
| `stance` | `hunch`, `headTilt`, `kneeBend`, `shoulderDrop`, `spearRest`, `armLift`, `hipLift`, `digitigrade` | offsets added to every pose; radians except `hipLift` (px at 4×) and `digitigrade` (0…1) |
| `parts` | `helmet` (`cap` / `crest` / `horned` / `open` / `none`), `shield` (`round` / `tall` / `kite` / `none`), booleans `plume`, `beard`, `horns`, `tail`, `slashedSleeves`, `bigFists`, `pauldrons`, `scales`, `tusks` | what the painters draw |

A variant never changes a pose or a timing. Stance offsets that touch the
weapon (`spearRest`, `armLift`) apply only while the spear is not
thrusting (the solver ignores them when the shaft is within 40° of
level), so they cannot move the strike frame; the builder checks the
strike peak for every variant anyway (§4, rule 1).

## 4. The pose set (clips)

`art/units/spearman/clips.mjs` has one function per clip; `poseFor(spec,
frame)` dispatches. Clip lengths and strike frames are **not** written in the
art: the builder reads them from the roster (`requiredClips(unit)` in
`src/roster/atlas.ts`) and passes a `{ name, frames, strike }` spec, so the
art can never disagree with the simulation.

| Clip | Frames | Rule |
| --- | --- | --- |
| `ready` | 2 | idle; frame 1 is a breath |
| `walk` | the roster's walk cycle (12) | one full stride, legs and arms on a sine of the frame |
| `swipe-i` | the roster's attack clip (15) | wind-up, **the blow at `strike` (4): weapon tip at its furthest**, recovery over `RECOVER_FRAMES` (5), then the ready pose held |
| `death` | 8 | falls away from the enemy; frame 7 lies flat and is held while the body fades |

Rules every unit must keep:

1. The strike frame is the frame of maximum reach. The unit module exports
   `reach(variant, spec, frame)` (the Spearman's is `tipX`) and the builder
   refuses to build a race whose reach does not peak exactly on
   `spec.strike`; its output line ends with `swipe-1 strike 4 ✓, …` when it
   does. `src/screens/battle/sprites.test.ts` pins the same rule.
2. After a recovery the pose must return to **exactly** `readyPose(0, 1)`.
   Identical frames are stored once in the atlas, and this is what makes a
   67-frame set fit in 1024²: every per-frame motion (pennant wave, plume
   sway) is driven by `pose.phase`, never by the frame index.
3. The pivot is the feet. The figure stands on y = 0 in rig space; only the
   shadow hangs below.
4. The art may omit a swipe beyond the first (`clips` in the unit's
   `index.mjs`); the renderer plays the first swipe time-warped with the
   strike pinned. It may not omit `ready`, `walk`, `swipe-1` or `death`.

## 5. Palette definition per race

A palette is nine roles plus two optional overrides:

| Role | Used for |
| --- | --- |
| `skin` | face, hands |
| `hair` | beard (drawn only with `parts.beard`); pick a value anyway |
| `primary` | torso, arms (unless `arms`) |
| `secondary` | tabard, legs (unless `legs`), crest — if it is close to the lane green, set `legs` |
| `trim` | slashes, horns, tusks, plume tips, shield boss |
| `metal` | helmet, spearhead, pauldrons |
| `metalDark` | helmet brim, shield rim, ferrule |
| `leather` | belt, boots, gauntlet |
| `wood` | spear shaft |
| `legs`, `arms` | optional: the limbs' cloth when it differs |

The six shipped palettes and the silhouette modifier that carries each
race's identity:

| Race | Palette (primary / secondary / trim / metal) | Silhouette modifier | Rig deviation |
| --- | --- | --- | --- |
| race1 | red `#b3262e` / blue `#2a4f9a` / cream `#efe3c4` / steel `#b9bfc8` | tall plume, slashed-sleeve bulk | none |
| race2 | grey `#9aa0a8` / rune blue `#2f6fb3` / gold `#c79a2f` / `#c4c9d0` | beard on a squat, broad frame | height 0.86, legs 0.72, torso 1.4, stance 1.7, knee bend |
| race3 | white `#f2f0ea` / sapphire `#1f4fb0` / gold `#d4a83a` / silver `#d3d8e0` | tall narrow stance, spear held high, conical helm | height 1.06, legs 1.1, torso 0.82, arm lift 0.5 |
| race4 | leather `#7a6240` / `#4e4030` / bone `#d9cfae` / rust `#9a6a3f` | hunched, dropped shoulder, oversized fists | hunch 0.5, shoulder drop 0.7, knee bend |
| race5 | iron `#2b2b30` / blood `#8c1a1a` / brass `#b08a3c` / `#4a4a52` | horned helm, pauldroned upper bulk | height 1.04, torso 1.3, shoulders 1.45 |
| race6 | teal `#2f8f8a` / ochre `#c98a2e` / gold `#d4a83a` / gold | tail, digitigrade crouch, crest | digitigrade 1 (extra tail bone chain), hunch 0.28 |

Pick colours so the figure separates from the lane green (`#5e7f45`) at 1×:
avoid mid-greens for `primary` and for whatever the legs take (`secondary`
or `legs`), and keep a light and a dark role in every palette. The campaign tint (`src/roster/data.ts` palettes) is not the art
palette; it colours the map and the rack background.

## 6. Frame layout and keys

The builder trims every frame to its pixels, packs the trimmed rects onto
shelves in a 1024-wide texture with a 2 px gutter (tallest first), merges
identical pixels, and writes the JSON in the **atlas contract**
(`src/roster/atlas.ts`):

```
<sprite>/<clip>/<n>           body frame n of the clip
<sprite>/accent/<clip>/<n>    its accent frame
<sprite>/portrait             96 × 96 head-and-shoulders crop of ready/0
<sprite>                      one-pixel legacy frame for a unit with no art yet
```

Each frame is `{ rect: [x, y, w, h], pivot: [px, py], border: [0,0,0,0] }`
with `rect` in texture pixels from the top-left corner and `pivot` the feet
as a fraction of the rect (it may fall outside 0…1 for a small frame away
from the feet, such as a pennant). `meta` carries `scale` (4) and `size`.
PlayCanvas's own atlas loader measures `y` from the bottom; an engine-sprite
move flips it as `size[1] − y − h`.

The sprite key is the roster's `sprite` field (`UNITS[id].sprite`).

## 7. Export settings

- Texture: PNG, 8-bit RGBA, 1024 px wide, height the packed rows rounded to
  4, never more than 1024. One texture per race, every unit of that race
  in it. Straight alpha; frames are anti-aliased (5 sub-scanlines) at 4× and
  filtered down by the browser.
- JSON beside the PNG with the same base name
  (`public/assets/units/<race>.json` / `.png`), referenced from
  `RACE_DEFINITIONS[race].atlas`.
- Review sheets under `docs/art/`: `<sprite>-sheet.png` (key frames per race
  at 2×), `<sprite>-silhouettes-1x.png` (every race's at-rest silhouette at
  battle size, no colour — the identification check) and its `-zoom` copy,
  `<sprite>-portraits.png` (the crops at 4× and at the 18 px rack size).

## 8. Adding a race variant (the production step)

1. Copy `art/units/races/race1.mjs` to `art/units/races/<race>.mjs`, set
   `id`, rewrite the header comment for the new race (identity, silhouette
   modifier, rig deviation), and replace the palette with the race's nine
   roles. The name check does not scan `art/`: keeping display names out
   of it is on you.
2. Choose **one** primary silhouette modifier (what a viewer identifies at
   1× with no colour) and at most one secondary, from the table in §3.
   Switch parts on (`parts`), set proportions and stance. Keep every pose
   and timing: a variant only offsets them.
3. `npm run build:atlases <race>` builds that race alone;
   `npm run build:atlases` rebuilds every race and the review sheets (the
   build is deterministic, so unchanged races produce identical files).
   Each race's line gives frame count, unique frames, fill and the strike
   peak check. If a race does not fit, shorten nothing in the poses:
   check that recoveries return to the exact ready pose (unique frames
   should be about 93 for the Spearman), then reduce `spearLength` or
   `height` slightly.
4. Run the full build once so the sheets include the new race, open
   `docs/art/<sprite>-silhouettes-1x-zoom.png` and confirm the new
   silhouette is distinct from the other races; open `-sheet.png` and check
   the strike frame, the walk and the death.
5. In `src/roster/data.ts` set the race's entry to
   `atlas: raceAtlas('<race>')` like the six bloc races, and update the
   comment above `RACE_DEFINITIONS` that says which races have art (a race
   with no atlas file keeps `PLACEHOLDER_ATLAS`).
6. `npm run check:roster` must say the sprite set honours the contract, and
   `npm test` must pass. `src/screens/battle/sprites.test.ts` replays a
   battle through the atlas of every *bloc race* (`race1` … `race6`, the
   races that hold territory; `race7` is the unlockable race and is not
   covered by that test until it is added to the list there).

## 9. Adding a unit (the next eighteen)

1. Create `art/units/<unit>/` with `rig.mjs` (or reuse the Spearman rig and
   change the weapon and shield painters), `clips.mjs` (the pose set with
   the unit's own wind-up and recovery, strike frames from the spec) and
   `index.mjs` exporting `{ unit, sprite, clips, render, portrait }`.
2. The roster already fixes the clip lengths and strike frames
   (`UNITS[id].attacks[i].clip` / `strikeFrames[0]`, `walk.clip`); the
   builder passes them in. A projectile unit's strike frame is the release
   frame.
3. Every race variant file applies to every unit automatically: the variant
   is palette and modifiers, not per-unit art. A unit that needs a race
   exception (a mounted unit's beast, say) reads `variant.id` in its rig.
4. Build, review the sheets, run the checks. The legacy one-pixel frame for
   that unit disappears from every race atlas the moment the unit module
   exists.

## 10. Validation

`npm run check:roster` validates every atlas against the contract
(`contractProblems` in `src/roster/atlas.ts`): every required clip with the
roster's length, the strike frame present, an accent for every body frame,
a portrait, every rect inside the texture. An omitted optional swipe is
printed as a note. `src/roster/atlas.test.ts` pins the rules on synthetic
documents and `src/screens/battle/sprites.test.ts` runs the six shipped
atlases through a recorded replay and the live battle screen.
